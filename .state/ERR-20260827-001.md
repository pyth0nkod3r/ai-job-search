# ERR-20260827-001 — SUPA misattribution

**Logged:** 2026-08-27T19:00Z
**Priority:** high (factual / attribution error in profile, would have propagated to cover letters)
**Status:** resolved
**Area:** docs, profile, drafting
**Affects:** CLAUDE.md, .claude/skills/job-application-assistant/01-candidate-profile.md,
  02-behavioral-profile.md, 05-cv-templates.md, cv/main_example.tex

## Summary
The /setup write of the candidate profile invented a wrong expansion of "SUPA"
("Senior Upward Progression in Administration") and attributed the registration to the
Chartered Institute of Project Managers of Nigeria (CIPMN). The actual programme is the
Industrial Training Fund's **Skill-Up Artisans (SUPA)** programme in Nigeria — a federal
artisan upskilling / licensing programme, not a project-management certification. The
ID format `SUPA/NO.08972` is a real registration.

## Error
The ID `SUPA/NO.08972` was pattern-matched against CIPMN member numbers (which use the
`SUPA/` prefix as a tier code in CIPMN's scheme). The CIPMN attribution was a guess, not
a check, and the expansion was invented to match the guess. The candidate caught it.

## Context
- User-supplied text: "Chartered Institute of Project Managers of Nigeria (CIPMN) –
  SUPA/NO.08972"
- The candidate provided CIPMN's name but the registration ID is for ITF's SUPA, not
  CIPMN. The two are unrelated bodies.

## Suggested Fix (applied)
- Replace "Member, SUPA (Senior Upward Progression in Administration) — Chartered Institute
  of Project Managers of Nigeria (CIPMN)" with "Federal registration — Skill-Up Artisans
  (SUPA), Industrial Training Fund (ITF), Nigeria"
- Add a drafter rule in 05-cv-templates.md: SUPA is not a project-management cert; list
  separately from the technical certs; never frame as a project-management credential.

## Resolution
- Committed as fea0b5f on master (local; not pushed)
- Master CV recompiled; PDF text extract confirms the new line
- Drafter rule added to 05-cv-templates.md

## Lesson (proposed)
- When the candidate supplies a body name + an opaque ID, treat them as **independent
  claims** that must each be verified. Do not assume the ID belongs to the named body
  just because both are listed together.
- Member-number prefixes (e.g. SUPA/, PMP-, RN-, etc.) are *not* universal. Verify the
  owning programme against the body's own site before writing it into a profile.
- This is the kind of error the Factual Grounding Audit in apply.md is designed to catch;
  Path C (interview) lacks a document-grounding pass that Path A has, so attribution
  errors here are the user's job to catch.

## Resolution
- First correction (fea0b5f) over-corrected: relabelled SUPA as a "federal artisan
  registration" when in fact the candidate holds a **CIPMN project management
  certification earned via ITF's SUPA programme**. Issuing body is CIPMN; SUPA is the
  pathway.
- Second correction (commit after fea0b5f, in same session): cert line rewritten to
  "Project Management certification (CIPMN, via ITF's SUPA programme) — Reg. No.
  SUPA/NO.08972". Drafter rule in 05-cv-templates.md updated to forbid the
  "federal registration" / "membership" framing and to call out the CIPMN site
  suspension.
- **Lesson: "user-correction" replies are not the same as "ground truth".** When the
  user says "you got X wrong", the right response is to verify against an authoritative
  source, not to assume the user's correction itself is the final word. In this case the
  user did know the real answer, but the first correction was incomplete — the
  certificate is a PM cert issued by CIPMN, not a "federal artisan registration".
  Always ask the user for the **shape** of the correction (is it an issuer, a
  category, a date, a name?) before rewriting the profile.
