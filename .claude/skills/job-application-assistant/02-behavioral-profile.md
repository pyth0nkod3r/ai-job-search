# Behavioral Profile

> **No formal assessment (PI, DISC, MBTI, StrengthsFinder) recorded.** Everything below
> is **inferred from documents in `documents/` plus work history**. Treat as a working
> hypothesis, not a fixed personality read.

## Strongest Behavioral Traits *[inferred]*

- **Builds end-to-end across the stack.** Eka Legal (Django/DRF + frontend), Interview
  Platform (full-stack with WebRTC-style real-time), the agentic Next.js app builder
  at Egoras, the Podcast Downloader Pipeline (Docker + Kestra + Postgres + Streamlit +
  Azure VM, deployed live), and the GFA client sites — every major project is owned
  from brief to deployment. Suggests the candidate defaults to "I'll do it" rather
  than "I'll find someone to do it", at least at current scale.

- **Self-directed learning at a high rate.** 16+ Coursera certs across three
  institutions, Stanford CS106A, the 3MTT DeepTech Ready program (data engineering
  mentorship), the Aspire Leaders Program (Harvard-based), the AI DevTools Zoomcamp
  (DataTalks.Club), and a self-funded NDE Level II certification. Most of this is
  outside employer sponsorship. The Portfolio's "What I Am Learning" section
  (Data Engineering, Backend Architecture, DevOps & Cloud, AI & Automation) is a
  stated growth agenda, not a resume filler.

- **Comfortable with production-grade infrastructure, not just code.** Self-hosted
  the Podcast Pipeline on an Azure B2s VM, runs 5 Docker services, deploys via
  Coolify, uses Traefik for routing, manages a custom domain, deploys Kestra flows
  via GitHub Actions with SMTP failure notifications, and operates a Postgres-to-
  Azure-SQL failover with cross-dialect translation. This is meaningfully above
  "tutorial-grade" comfort with the stack.

- **Operates across domains without flinching.** Carrier has moved between
  ultrasonic NDT (with a real ASNT-aligned Level II cert), telecom BTS field
  engineering, full-stack software, network infrastructure, an agentic AI
  product, and full-stack data engineering — across roughly 8 years. Each step
  was a deliberate, evidence-backed move (a new cert stack, a new program, a
  new domain toolset), not a random job-hop.

- **Carries both engineering and software without choosing.** Bridge profile —
  strongest in roles that combine software with physical / embedded / systems
  / data context. The recent Podcast Pipeline is data engineering done in
  production, not in a tutorial.

- **Willing to operate in resource-constrained environments and ship anyway.**
  Spot-instance VM with auto-shutdown rules, B2s (2 vCPU / 4 GB RAM / 50 GB disk
  by choice), 5-service stack on a single box, Kestra over Airflow for the
  YAML cleanliness, Streamlit over Metabase because the codebase is version-
  controlled in Git. Implies the candidate is willing to make pragmatic
  trade-offs to ship.

- **Open to risk and change.** "Open to offers" + "willing to relocate" +
  the cross-domain track record. The Portfolio's "Where I Am Now" line:
  *I recently completed a data engineering program and I am actively
  learning, building and looking for opportunities to grow.* Reads as
  honest, not aspirational.

- **Honest about scope and limits.** The Portfolio explicitly says *"I have
  built Django REST APIs, but I want to understand more about microservices,
  caching and scaling applications beyond a single server."* — that kind of
  "I have built X but I want to learn Y" honesty is the opposite of
  overclaiming, and the drafter should mirror it.

## How Miracle Works Best *[inferred]*

- Projects with a clear ship target and a real user at the other end (cube-os
  has both; the BEng thesis had both; the Podcast Pipeline has both, with a
  public live dashboard and a public capstone report).
- Teams that move quickly and give ownership ("you own this surface area").
- Roles that combine software with some physical / embedded / systems / data
  context — the candidate's full self isn't being used if the work is pure
  front-of-screen.
- Async / remote setups with a written culture, given the GFA / Egoras /
  Podcast Pipeline track record.
- Programs that take a candidate seriously and let them ship (3MTT, ALX
  Ventures, Aspire) have all produced major deliverables — the candidate
  thrives in that context.

## What Drains *[inferred]*

- Pure maintenance work with no clear product surface to ship to.
- Roles that require years of single-stack specialism the candidate does
  not have (e.g. "5 years of pure backend on Java Spring in a financial
  institution" — the candidate is full-stack + data + embedded, and would
  have to over-claim to be competitive).
- Long on-site commitments with no remote flexibility, given the track
  record.
- Roles gated on Spanish or German at C1+ — the candidate has these at A1
  only and would either need to upskill fast or be flagged honestly.

## Management Style Preferences *[inferred]*

- Wants to be told the *what* and own the *how* — the build-end-to-end
  pattern suggests low need for task-level supervision.
- Comfortable with feedback on shipped work; less comfortable with process
  for its own sake.
- Responds well to programs that combine mentorship with shipping
  (3MTT, ALX, Aspire) — these produced the strongest outputs in the
  candidate's history.

  (full-stack ownership), the live production deployment with CI/CD.
